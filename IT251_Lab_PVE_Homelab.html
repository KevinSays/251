Hands-On · Homelab

What this lab covers

A homelab is a small set of servers you own and are allowed to break. People use them to practice for jobs they don't have yet. By the end of this lab you'll have your own Proxmox VE server. It will run two Linux containers on their own network, including a web server you can reach from your laptop's browser, and you'll write a README documenting the whole setup. You'll keep using it after this lab.

Read first

Can my laptop run this?

Proxmox is normally installed directly on a server ("bare metal"). In class we'll run it inside a VirtualBox VM instead. Running one hypervisor inside another is called nested virtualization, and it needs more from your computer than your other lab VMs did.

Before Session 1 · at home

Pre-lab: download and verify

The installer is about 1.7 GB. Download it at home, not over campus Wi-Fi during class.

  1. Go to proxmox.com/en/downloads and download the latest Proxmox VE ISO Installer. Use the regular one, not the one labeled "For ARM64".
  2. On the same page, copy the SHA256 checksum listed for that ISO.
  3. Verify the download. This is the same habit as the checksum callout in the Week 4 tooling lab: never install an OS you haven't verified. 
    # Linux
sha256sum ~/Downloads/proxmox-ve_*.iso

# macOS
shasum -a 256 ~/Downloads/proxmox-ve_*.iso

# Windows (PowerShell)
Get-FileHash $HOME\Downloads\proxmox-ve_*.iso -Algorithm SHA256
    Compare the output with the checksum from the website. If they don't match, download it again.
  4. Make sure you have at least 70 GB free on your laptop's drive. The virtual disk starts small and grows as you use it.

Understand before you click

The design

Before you build anything, know where every address comes from. This is the network you're making:

YOUR LAPTOP (the VirtualBox host) ├── browser ──► https://192.168.56.10:8006 (Proxmox web UI) │ browser ──► http://192.168.56.21 (nginx in container web01) │ │ host-only network "vboxnet0" 192.168.56.0/24 your laptop is .1 │ ════════════════════════════╤══════════════════════════════ │ │ Adapter 1 (promiscuous: Allow All) │ ┌───────────────────────────┴────────────────────────────┐ │ │ PROXMOX VE VM pve.homelab.lan │ │ │ vmbr0 192.168.56.10/24 ◄── Linux bridge │ │ │ ├── CT 101 web01 192.168.56.21 (gateway .10) │ │ │ └── CT 102 db01 192.168.56.22 (gateway .10) │ │ │ │ │ │ NAT out (masquerade) ──► enp0s8 10.0.2.15 (static) │ │ └─────────────────────────────────┬───────────────────────┘ │ │ Adapter 2: VirtualBox NAT └──────────────────────────────── internet
Why two adapters?

One for you to reach in, one for it to reach out

The host-only adapter is a private network between your laptop and the VM. You can reach Proxmox and the containers at fixed addresses, but nothing on that network can reach the internet. The NAT adapter is the reverse: it can reach the internet, but your laptop can't easily reach in. Proxmox's own guide for running inside VirtualBox recommends exactly this pair.

The Proxmox host then acts as the router for its containers. Their traffic leaves through the host, which rewrites it to look like the host's own traffic. This is called masquerading, and your home router does the same thing for your phone and laptop.

Concept

VMs vs. containers

A VM (KVM/QEMU in Proxmox) emulates a whole computer and runs its own kernel. It can run any operating system, Windows included, but it uses a lot of RAM and CPU. A container (LXC in Proxmox) shares the host's Linux kernel and keeps only its processes, files, and network separate. It starts in about a second and uses a fraction of the memory, but it can only run Linux. Containers are the required part of this lab because they work even where nested VMs don't.

Session 1

Part A · Build the VirtualBox VM

  1. Check that the host-only network exists. In VirtualBox, go to File → Tools → Network Manager → Host-only Networks. You should see one at 192.168.56.1/24. It's usually named vboxnet0 on Linux and macOS, or "VirtualBox Host-Only Ethernet Adapter" on Windows. If there isn't one, click Create.
  2. Create a new VM: name PVE-Lab, choose the Proxmox ISO, type Linux, version Debian (64-bit). Tick Skip Unattended Installation if it's offered.
  3. Hardware: 4096 MB RAM (6144 if you have 16 GB or more), 2 CPUs (4 if you have them).
  4. Disk: 64 GB, dynamically allocated.
  5. Before the first boot, open the VM's Settings:
    • System → Processor: tick Enable Nested VT-x/AMD-V. If the box is greyed out, close the VirtualBox window and run this on your laptop instead: 
      VBoxManage modifyvm "PVE-Lab" --nested-hw-virt on
    • Audio: untick Enable Audio.
    • Network → Adapter 1: set Attached to Host-only Adapter and choose vboxnet0 (or the Windows equivalent). Expand Advanced and set Promiscuous Mode to Allow All. Write down the MAC address shown here.
    • Network → Adapter 2: tick Enable and set Attached to NAT. Use plain "NAT", not "NAT Network".
Why "Allow All"? Each container gets its own MAC address on Adapter 1. By default, VirtualBox only delivers traffic addressed to the VM's own MAC address, so your containers would never receive a reply. Promiscuous mode tells VirtualBox to pass all traffic through to the VM, where the vmbr0 bridge delivers it to the right container.

Session 1

Part C · Post-install: network, repos, updates

Proxmox is installed, but it can't reach the internet yet and it's pointed at a paid update channel. Fixing both is ordinary Debian administration. From here on, work in the web UI's Shell (click pve in the left tree, then >_ Shell), or SSH in from your laptop: ssh root@192.168.56.10.

C1 · Diagnose first

ip -br link          # your two NICs: names like enp0s3 and enp0s8
ip -br addr          # which one has an address?
ip route             # where does "default" point?
ping -c 3 1.1.1.1            # can we reach the internet by IP?
ping -c 3 deb.debian.org     # ...and by name?

Both pings fail. The name lookup fails first, with "Temporary failure in name resolution", but DNS isn't the real cause. ip route shows why: the default route goes to 192.168.56.1, which is your laptop on the host-only network, and that network doesn't lead to the internet. The second NIC, the NAT one, has no address at all, so neither the internet (1.1.1.1) nor the DNS relay (10.0.2.3) is reachable. Fix the lowest layer first, and the DNS error goes away by itself. This is the method from the 7.1 Troubleshooting Primer: find the evidence before you change anything.

C2 · Fix the network

Back up the file, then edit it:

cp /etc/network/interfaces /root/interfaces.orig
nano /etc/network/interfaces

Make it look like this, using your NIC names from ip -br link. Adapter 1 is the NIC already listed in bridge-ports. Adapter 2 is the other one. The installer may have added an iface enp0s8 inet manual line for Adapter 2, so replace it rather than adding a second one. Each interface should appear only once.

auto lo
iface lo inet loopback

iface enp0s3 inet manual

auto vmbr0
iface vmbr0 inet static
        address 192.168.56.10/24
        # gateway line REMOVED - the default route now comes from enp0s8
        bridge-ports enp0s3
        bridge-stp off
        bridge-fd 0
        # Route the containers' traffic out through the NAT adapter:
        post-up   echo 1 > /proc/sys/net/ipv4/ip_forward
        post-up   iptables -t nat -A POSTROUTING -s '192.168.56.0/24' -o enp0s8 -j MASQUERADE
        post-down iptables -t nat -D POSTROUTING -s '192.168.56.0/24' -o enp0s8 -j MASQUERADE

auto enp0s8
iface enp0s8 inet static
        address 10.0.2.15/24
        gateway 10.0.2.2

Why static, not DHCP? VirtualBox's NAT adapter always uses the same addresses: the guest is 10.0.2.15, the gateway is 10.0.2.2, and DNS is 10.0.2.3. Typing them in avoids depending on a DHCP client being installed.

Apply it without rebooting, then verify:

ifreload -a
ip route                       # default via 10.0.2.2 dev enp0s8
cat /proc/sys/net/ipv4/ip_forward   # 1
ping -c 3 deb.debian.org       # replies now
What each line does

A bridge, a route, and a translation

vmbr0 is a Linux bridge, a virtual switch. bridge-ports enp0s3 plugs the VM's network card into it, and every container you create gets plugged in too. Setting ip_forward to 1 lets the kernel pass packets between interfaces, which turns the host into a router.

The MASQUERADE rule rewrites the source address of any traffic from 192.168.56.0/24 that leaves through enp0s8. Replies come back to the host, which forwards them to the right container. This snippet is adapted from Proxmox's own network documentation.

C3 · Switch to the free update repository

Proxmox sells support subscriptions, and a fresh install points apt at the enterprise repository, which needs a paid key. If you run apt update now, you'll see 401 Unauthorized errors. To fix it, you'll edit apt sources in the deb822 .sources format, the newer style that Debian 13 uses:

ls /etc/apt/sources.list.d/
cat /etc/apt/sources.list.d/pve-enterprise.sources

Disable the enterprise repos by adding one line, Enabled: no, to each entry:

nano /etc/apt/sources.list.d/pve-enterprise.sources   # add:  Enabled: no
nano /etc/apt/sources.list.d/ceph.sources             # add:  Enabled: no  (if the file exists)

Then add the free no-subscription repository:

cat > /etc/apt/sources.list.d/proxmox.sources <<'EOF'
Types: deb
URIs: http://download.proxmox.com/debian/pve
Suites: trixie
Components: pve-no-subscription
Signed-By: /usr/share/keyrings/proxmox-archive-keyring.gpg
EOF
apt update
apt full-upgrade -y

Check your work in the web UI: under pve → Updates → Repositories, the no-subscription repo should be enabled and the enterprise ones disabled. The free repo ships the same software as the enterprise one, but with less testing before release. That's fine for a homelab, but a business wouldn't run it. The "No valid subscription" popup will keep appearing at login. That's normal; just click OK.

Snapshot time: shut down the VM (poweroff) and take a VirtualBox snapshot named pve-installed. You can roll back to this point if anything later goes wrong.

Part D · Your first container (web UI)

D1 · Download a template

A container template is a ready-made Linux root filesystem, compressed into one file. In the left tree, go to local (pve) → CT Templates → Templates. Search for debian, choose the newest debian-13-standard, and click Download.

D2 · Create the container

Click Create CT (top right) and fill in:

Create CT wizard
TabSetting
GeneralCT ID 101, hostname web01, a root password. Leave Unprivileged container ticked (Part G explains why).
TemplateStorage local, the debian-13-standard template
DisksStorage local-lvm, 8 GB
CPU / Memory1 core, 512 MB memory, 512 MB swap
NetworkBridge vmbr0, IPv4 Static: 192.168.56.21/24, gateway 192.168.56.10 (the Proxmox host, which is now a router)
DNSLeave blank to use the host's settings

D3 · Make it do something

Select 101 (web01) → Console, log in as root, and run:

ip -br addr                 # 192.168.56.21 on eth0
ping -c 3 deb.debian.org    # internet works through the host's NAT
apt update && apt install -y nginx
systemctl status nginx      # active (running), same systemd as your VMs
echo "web01 - my homelab works" > /var/www/html/index.html

Now, in your laptop's browser, go to http://192.168.56.21. That page is served by a container, running in a hypervisor, inside a VM, on your laptop.

Hint: ping or apt fails inside the container

Work outward one hop at a time, as in the 7.1 Troubleshooting Primer:

  • If ping -c 3 192.168.56.10 (the gateway) fails, the problem is in Part A. Check that promiscuous mode is set to Allow All on Adapter 1.
  • If the gateway answers but ping -c 3 1.1.1.1 doesn't, check the Proxmox host. Is ip_forward set to 1? Does iptables -t nat -L POSTROUTING -n show the MASQUERADE rule?
  • If 1.1.1.1 answers but deb.debian.org doesn't, the problem is DNS. Check cat /etc/resolv.conf in the container.

D4 · Log in like a sysadmin

The console is for emergencies. Make a normal user in web01 and SSH in from your laptop:

# in the web01 console
adduser student             # pick a password
usermod -aG sudo student

# on your laptop
ssh student@192.168.56.21

If you get "Connection refused", the template didn't include an SSH server. Run apt install -y openssh-server in the console. SSH as root with a password is refused on purpose: Debian's default setting PermitRootLogin prohibit-password is a security measure, so leave it in place.

Session 2

Part E · Snapshot, break, roll back

This is why homelabs use hypervisors: undo takes one click, so you can experiment freely.

  1. Select web01 → Snapshots → Take Snapshot, and name it nginx_working.
  2. Break it. In web01, as root: 
    rm -rf /etc/nginx
systemctl restart nginx     # fails - read why with: journalctl -u nginx -n 10
    Refresh http://192.168.56.21 in your browser: the site is down.
  3. Roll back: Snapshots → select nginx_working → Rollback. Start the container again if it stopped.
  4. Refresh the browser. Your custom page is back.
A snapshot is not a backup. It lives on the same disk as the container, so if the disk dies, the snapshot dies with it. Proxmox makes real backups with vzdump (Datacenter → Backup). The same rule applies to your VirtualBox snapshots: they protect you from bad changes, not from hardware failure.

Session 2

Part F · Do it again from the command line

Every action in the web UI has a command behind it. Real admins script repetitive jobs, and the exam expects you to know the GUI isn't the only way. From the Proxmox host's shell:

pveam update                                  # refresh the template catalog
pveam available --section system | grep debian
pveam list local                              # templates you already downloaded
pct list                                      # containers that exist

Create db01 with one command. Copy the exact template name from pveam list local:

pct create 102 local:vztmpl/debian-13-standard_<VERSION>_amd64.tar.zst \
  --hostname db01 \
  --memory 512 \
  --rootfs local-lvm:8 \
  --net0 name=eth0,bridge=vmbr0,ip=192.168.56.22/24,gw=192.168.56.10 \
  --unprivileged 1 \
  --password 'Change-Me-251'

pct start 102
pct list
pct exec 102 -- ip -br addr
pct exec 102 -- ping -c 3 192.168.56.21      # db01 can reach web01
pct exec 102 -- passwd                        # now change that password
Notice what you just did: you typed a password on the command line. It's now in the root user's shell history (history | grep password), which is why the next command changes it. In a real script you'd use --ssh-public-keys instead.
Hint: "unable to parse" or "volume does not exist"

The template name must match exactly, including the version and the .tar.zst ending. Run pveam list local and copy the local:vztmpl/… value from its output. Each backslash must be the very last character on its line, with no space after it.

Part G · Under the hood

Proxmox is Debian with extra packages. Run each command on the Proxmox host, and write a one-line answer to each question in your README.

G1 · Services

G2 · Storage

Where do container disks live?

lsblk

pvesm status

Q: Find web01's disk in the lvs output. Which volume group is it in? Why does Data% show much less than 8 GB in use? (Hint: "thin" provisioning.)

G3 · Config files

The web UI is editing text files

pct config 101
cat /etc/pve/lxc/101.conf
mount | grep /etc/pve

Q: What kind of filesystem is mounted on /etc/pve? (It's Proxmox's cluster filesystem. In a cluster of several servers, every node sees the same files here.)

G4 · Permissions

Unprivileged containers: root isn't root

pct exec 101 -- ps -o user,pid,cmd -C nginx   # inside: run by root and www-data
ps -o user,pid,cmd -C nginx                    # on the host: the same processes

Q: Which user does the host say owns the nginx master process? Inside an unprivileged container, UID 0 is mapped to UID 100000 on the host. Why does that matter if someone breaks out of the container?

G5 · Hypervisor

Is hardware virtualization available?

grep -cE 'vmx|svm' /proc/cpuinfo
ls -l /dev/kvm

Q: If the count is above 0 and /dev/kvm exists, nested virtualization is working and full VMs will run. What did yours show? What's the difference between a Type 1 and a Type 2 hypervisor, and which type is Proxmox? Which is VirtualBox?

Sidebar · bare metal

Installing on a real spare PC

Write the ISO to a USB stick (balenaEtcher, Rufus in DD mode, or dd). Turn on VT-x/AMD-V in the BIOS; it's often labeled "SVM" or "Virtualization Technology". Then install. The installer erases the whole target disk.

Use your home network's addresses instead of 192.168.56.x: pick a free static IP outside your router's DHCP range, and use your router as the gateway. You won't need Part C2 at all, because a single NIC on a real network already has internet access, and you won't need promiscuous mode. Never plug a homelab into the campus network.
