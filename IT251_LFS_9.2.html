Every session · keep long builds alive

Work inside tmux

A build runs inside your SSH window. If that window closes, your Wi-Fi drops, or you close your laptop's terminal, the build is killed halfway. tmux fixes this: it keeps your session running inside the VM, and you can reconnect to it later. Start it first every time you sit down to build, as student, before sudo -i:

tmux new -s lfs          # first time: start a session named "lfs"
tmux attach -t lfs       # every time after: reconnect to it (also after an SSH drop)
  • To leave a build running and close the window, press Ctrl+b, let go, then press d ("detach"). The build keeps going.
  • A green bar at the bottom of the window means you're inside tmux.
  • If tmux attach says no sessions, the VM was rebooted (that ends tmux too). Start a new one, run your resume card, and redo the package you were on.
  • tmux can't help if your laptop goes to sleep, because the whole VM pauses. See Keep your laptop awake.

Lab 9.2 · Session 1

Prepare the disk, the user, and measure your SBU

Week of Oct 19 · Book: Chapters 2–4, then §5.2 · Milestone M1 · Homework: finish Chapter 5

Step 1 · Read first (Ch. 1–2)

Skim §2.2 Host System Requirements. Your version-check.sh already passed, because the class VM was built to meet them. Read §2.3 carefully; it's the reason for the resume cards, which you'll start using after today.

Step 2 · Partition the LFS disk (§2.4)

Become root and prove you have the right disk before touching it:

sudo -i
lsblk /dev/sdb           # must say 30G and show NO partitions under it

If sdb isn't 30G and empty, stop and ask. Then create one partition on a classic MBR ("dos") partition table:

fdisk /dev/sdb
  o        # new empty DOS (MBR) partition table
  n        # new partition
  p        # primary
  1        # partition number 1
  Enter    # default first sector
  Enter    # default last sector (use the whole disk)
  w        # write and quit
lsblk /dev/sdb           # now shows sdb1
Why MBR and not GPT? Our VMs boot with legacy BIOS. With an MBR disk, GRUB needs nothing extra. A GPT disk on BIOS needs an extra tiny "BIOS boot" partition (the book explains it in Chapter 10). Same result, fewer moving parts. We skip swap: the host VM already has some.

Step 3 · Filesystem, $LFS, mount (§2.5–2.7)

mkfs -v -t ext4 /dev/sdb1
echo $LFS ; umask        # /mnt/lfs and 0022 (the class VM sets both for root)
mount -v -t ext4 /dev/sdb1 $LFS
findmnt $LFS

Now make it mount automatically every boot. The nofail option means that if the disk is ever missing, Debian still boots instead of dropping you into emergency mode:

echo "UUID=$(blkid -s UUID -o value /dev/sdb1)  /mnt/lfs  ext4  defaults,nofail  0 0" >> /etc/fstab
systemctl daemon-reload
umount $LFS && mount -a && findmnt $LFS     # proves the fstab line works

Step 4 · Sources (§3.1)

Create the sources directory exactly as §3.1 says (mkdir + chmod a+wt). Then, instead of downloading again, copy what you downloaded at home and re-check it in its new home:

cp -v ~student/lfs-sources/* $LFS/sources/
cd $LFS/sources && md5sum -c md5sums | grep -v ': OK$' ; cd
chown root:root $LFS/sources/*

Step 5 · Layout, the lfs user, the clean environment (Ch. 4)

Do §4.2, §4.3 and §4.4 exactly as written. Things people miss:

  • §4.4 moves /etc/bash.bashrc out of the way. Debian has this file, so do that step.
  • §4.4 ends by adding MAKEFLAGS=-j$(nproc) to the lfs user's .bashrc and running source ~/.bash_profile. Do both.
  • Check yourself with Card 2: prompt lfs:~$, and $PATH starts with /mnt/lfs/tools/bin.
Why it matters

Least privilege, for real

The book builds Chapters 5–6 as a throwaway, unprivileged lfs user with a scrubbed environment (env -i). If a command is mistyped, it fails with "Permission denied" instead of overwriting files in your host's /usr. That's the same idea as running a web server as www-data instead of root, which is Module 5 material.

Step 6 · Measure your SBU (§4.5 + §5.2)

Read §4.5 About SBUs and General Compilation Instructions. The SBU (Standard Build Unit) is how long Binutils pass 1 takes on one core on your machine. Every other build time in the book is a multiple of it.

  1. Plug in your laptop and set it to performance power mode. Make sure it won't sleep (how), and work inside tmux.
  2. As lfs, follow §5.2. Extract the tarball and cd in, then create and enter build.
  3. Wrap the configure/make/install in time { … } as the book's note shows. Use make -j1 for this one package, because the SBU is defined on a single core: 
    time { ../configure --prefix=$LFS/tools ...(rest exactly as in §5.2)... && make -j1 && make install; }
  4. Write down the real time. That's your SBU.
  5. Clean up: cd $LFS/sources && rm -rf binutils-2.47. From now on, keep the book's normal MAKEFLAGS (all cores).
