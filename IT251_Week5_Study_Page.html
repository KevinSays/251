Package management

Remove it, but keep the config

You want to uninstall a package on a Debian-family system but keep its configuration files in case you reinstall it later.

Show answer 
sudo apt remove packagename

remove uninstalls the package but leaves config files behind; purge removes those too. Use purge only when you want a truly clean slate.

Systemd

Started, but won't survive a reboot

A service is running right now (systemctl status shows active) but after a reboot, it's gone.

Show answer

Diagnosis: it was started manually but never enabled — active/inactive (now) and enabled/disabled (boot-time) are independent.

sudo systemctl enable servicename
Containers

Data disappeared after removing a container

A container was writing to a file inside itself. After docker rm, that data is gone.

Show answer

Why: a container's writable layer is discarded when it's removed — anything not stored outside the container doesn't survive.

docker run -v mydata:/app/data myimage

A named volume (or bind mount) persists data outside the container's lifecycle — the fix is to mount one before the data matters, not after.

Repository management

apt update fails with a signature error

After adding a new third-party repository, sudo apt update fails with something like "NO_PUBKEY" or "signatures couldn't be verified."

Show answer

Diagnosis: the repo's GPG signing key hasn't been imported yet — apt refuses to trust packages it can't cryptographically verify came from that repo, which is the whole point of repo signing.

Fix: import the repository's public key (the exact command is provided by whoever publishes the repo, typically an apt-key add or a key file dropped into /etc/apt/trusted.gpg.d/ on modern Debian/Ubuntu), then re-run apt update. Never work around this by disabling signature checks — that defeats the entire protection.

update-alternatives

Two Python versions, one command

A system has both Python 3.9 and 3.11 installed. Running python3 always launches 3.9, but a script needs 3.11's features.

Show answer 
sudo update-alternatives --config python3

This lists every registered alternative for python3 and lets you pick which one /usr/bin/python3 actually symlinks to — without uninstalling either version or touching $PATH manually.

Container networking

Can't reach the container from outside

A web app is running fine inside a container (confirmed with docker exec ... curl localhost:8080), but the host machine's browser can't reach it at all.

Show answer

Diagnosis: the container's port was never published to the host — by default, a container's ports are only reachable from inside the container's own network namespace.

docker run -p 8080:8080 myimage

-p host:container maps a host port to the container's port — without it, the app is running but genuinely unreachable from outside, which is different from a firewall or crash problem.
