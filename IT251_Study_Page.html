Overview

What Week 1 covers

Before you can troubleshoot a Linux box, you need to know what happens between pressing the power button and seeing a prompt — and where things live once you're in. This week is the map: boot sequence, directory structure, distro families, and the tools that manage devices and kernel modules underneath it all.

  • Trace the boot process from firmware to a running shell
  • Navigate the FHS confidently and explain what each top-level directory is for
  • Compare Debian-family and RHEL-family distros and their package managers
  • Load, unload, and inspect kernel modules
  • Explain what initramfs does and why it exists
  • Build a personal Linux VM and set up persistent terminal logging (Wednesday's hands-on lab)

Boot troubleshooting

Where did it stop?

A server hangs on a blinking cursor before any boot menu ever appears — no GRUB menu, nothing.

Show answer

Stage: This is failing before the bootloader even loads — likely a firmware/BIOS-UEFI issue or a corrupted/missing bootloader on the disk, not a kernel or initramfs problem.

Why it matters: knowing the stage narrows your fix — a missing GRUB entry needs a rescue disk and grub-install, not a kernel parameter change.

Kernel modules

Load it, prove it, unload it

You need to load the usb_storage module, confirm it's active, then remove it.

Show answer 
modprobe usb_storage
lsmod | grep usb_storage
modprobe -r usb_storage

modprobe handles dependencies for you (unlike insmod/rmmod), which is why it's the go-to command day to day.

FHS

Where would you look?

A web server is misbehaving and you need to check its error log, and separately, find where a newly installed package put its shared libraries.

Show answer

Error log: /var/log/ — that's where variable, frequently-changing data like logs lives.

Shared libraries: under /usr/lib (or /usr/lib64) — the bulk of installed software and its dependencies live under /usr.
