Create the VM

In VirtualBox: Machine → New

  • Name: IT251-<yourname>
  • Type/Version: match your distro (e.g., Linux / Ubuntu 64-bit)
  • Memory: 4096 MB minimum (2048 MB floor if the host is low on RAM)
  • CPU: 2 cores
  • Disk: 25 GB, dynamically allocated, VDI format
  • Attach the ISO under Storage → Optical Drive

Install the distro

Boot the VM and run the installer: language/keyboard, disk (use the whole virtual disk — no dual-boot risk, it's not real hardware), create a user account you'll remember all semester — this is what you'll be graded through.

Debian / Ubuntu / Mint 
sudo apt update && sudo apt upgrade -y
Fedora 
sudo dnf upgrade -y
Shut down, then snapshot: Machine → Take Snapshot, name it clean-install. This is your safety net for the rest of the semester — break the VM later, roll back instead of reinstalling from scratch.

Persistent terminal history logging

This is the piece that makes every future lab auto-generate proof of work — run this once, and it keeps logging every session from here on. Open a terminal in your VM:

nano ~/it251-setup-logging.sh

Paste this in, save, exit — or skip the copy-paste and download the script directly instead:

#!/usr/bin/env bash
# IT251 - persistent terminal history logging setup. Run once.
set -euo pipefail

MARKER_START="# >>> IT251 history logging >>>"
MARKER_END="# <<< IT251 history logging <<<"
LOG_DIR="$HOME/IT251/logs"

case "$SHELL" in
  */zsh) RC_FILE="$HOME/.zshrc" ;;
  *)     RC_FILE="$HOME/.bashrc" ;;
esac

mkdir -p "$LOG_DIR"

if grep -qF "$MARKER_START" "$RC_FILE" 2>/dev/null; then
  echo "Logging block already present in $RC_FILE - nothing to do."
else
  {
    echo ""
    echo "$MARKER_START"
    if [[ "$RC_FILE" == *zshrc ]]; then
      cat <<'ZSH'
export HISTFILE="$HOME/.zsh_history"
HISTSIZE=100000
SAVEHIST=100000
setopt INC_APPEND_HISTORY
setopt EXTENDED_HISTORY
ZSH
    else
      cat <<'BASH'
export HISTFILE="$HOME/.bash_history"
export HISTTIMEFORMAT="%F %T  "
export HISTSIZE=100000
export HISTFILESIZE=100000
shopt -s histappend
PROMPT_COMMAND="history -a; history -c; history -r${PROMPT_COMMAND:+; $PROMPT_COMMAND}"
BASH
    fi
    echo "$MARKER_END"
  } >> "$RC_FILE"
  echo "Added logging config to $RC_FILE."
fi

echo "Done. Run: source $RC_FILE   (or open a new terminal) then check with: history | tail"

Run it and reload your shell:

bash ~/it251-setup-logging.sh
source ~/.bashrc      # or: source ~/.zshrc
What does this actually do?

Every command gets a timestamp (HISTTIMEFORMAT). History writes to disk immediately after each command instead of only on exit, so a crash doesn't lose the log. History size is raised so a full semester of commands doesn't get silently truncated. HISTFILE is explicitly exported so the export script below (which runs as its own process) can actually see it — without this, the export script fails on the very first run. The block is idempotent — running the script again won't duplicate it.

Second script — an export helper you'll reuse at the end of every future lab:

nano ~/it251-export-log.sh

Download this one directly instead, if you'd rather not paste it in:

#!/usr/bin/env bash
# IT251 - export current history to a timestamped file for lab submission.
set -euo pipefail

LOG_DIR="$HOME/IT251/logs"
mkdir -p "$LOG_DIR"
STAMP="$(date +%Y%m%d_%H%M%S)"
OUT="$LOG_DIR/history_${STAMP}.txt"

history -a   # flush current session's history to disk first
cp "${HISTFILE:-$HOME/.bash_history}" "$OUT"

echo "Exported history to: $OUT"
echo "Submit this file (or the whole ~/IT251/logs folder) as lab proof."
chmod +x ~/it251-export-log.sh

Verify & submit

Navigation

pwd
cd /
ls
cd /home
ls
cd ~
pwd

pwd — where am I. cd — absolute vs. relative paths, ~, .., - for "previous directory". ls vs ls -l vs ls -la.

File & directory operations

mkdir ~/lab2-practice
cd ~/lab2-practice
touch notes.txt
mkdir subdir
cp notes.txt subdir/notes-copy.txt
mv notes.txt renamed-notes.txt
ls -l
rm subdir/notes-copy.txt
rmdir subdir      # only works if empty
No trash can: rm deletes for real. rmdir only removes empty directories; rm -r is recursive and deletes contents too — double-check the target before hitting enter, especially with wildcards.

Viewing files, redirection, man

echo "first line" > notes.txt
echo "second line" >> notes.txt
cat notes.txt
head -n 1 notes.txt
tail -n 1 notes.txt
less notes.txt        # q to quit
man ls

> overwrites, >> appends. | (pipe) sends one command's output into the next, e.g. ls -la | less. man <command> is the answer to "what does this flag do" for the rest of the semester.

Build your scavenger course

Create the setup script — it builds a personal ~/IT251/scavenger/level0 through level5 tree, each level hiding a password behind one FHS/permissions trick. Open a terminal in your VM:

nano ~/it251-scavenger-setup.sh

Paste this in, save, exit — or skip the copy-paste and download the script directly instead:

#!/usr/bin/env bash
# IT251 Lab 3 - local FHS/permissions scavenger hunt. Run once.
set -euo pipefail

BASE="$HOME/IT251/scavenger"
rm -rf "$BASE"
mkdir -p "$BASE"/{level0,level1,level2,level3,level4/deep/deeper,level5}

# Level 0: hidden dotfile
echo "PASSWORD-0: you found a dotfile with ls -la" > "$BASE/level0/.secret"

# Level 1: awkward filename (leading dash + spaces)
echo "PASSWORD-1: quoting/escaping beats a filename that looks like a flag" > "$BASE/level1/--not a flag--.txt"

# Level 2: unreadable until chmod'd
echo "PASSWORD-2: chmod got you read access" > "$BASE/level2/locked.txt"
chmod 000 "$BASE/level2/locked.txt"

# Level 3: needle in decoys, findable by exact size
echo -n "PASSWORD-3: found by exact size with find -size" > "$BASE/level3/needle.txt"
for i in 1 2 3 4 5; do
  head -c $((RANDOM % 500 + 10)) /dev/urandom | base64 > "$BASE/level3/decoy-$i.txt"
done

# Level 4: buried in a nested tree
echo "PASSWORD-4: find from the top with -name, no manual cd chain needed" > "$BASE/level4/deep/deeper/target.txt"

# Level 5: symlink to follow
echo "PASSWORD-5: ls -l shows the arrow, readlink shows the target" > "$BASE/level5/real-answer.txt"
ln -s "$BASE/level5/real-answer.txt" "$BASE/level5/shortcut"

echo "Scavenger course built at $BASE"

Run it:

bash ~/it251-scavenger-setup.sh
Same loop as OverTheWire Bandit — find the trick, read the password, move to the next level — just running entirely inside your own VM instead of over SSH. (Bandit itself is still there as optional extra practice if you want more reps — see the LMS.) The script is idempotent — re-running it (e.g. before Week 6's timed checkpoint) rebuilds a fresh course, safe to run more than once.

Demo: Level 0 (hidden files)

cd ~/IT251/scavenger/level0
ls
ls -la
cat .secret

ls hides dotfiles by default; -a shows them. This is a convention for reducing clutter, not access control — don't confuse it with real security.

Levels 1–5 — work at your own pace

Stuck? Hints

Level 1: the shell reads a leading -- as flags unless you tell it otherwise — cat -- "--not a flag--.txt".

Level 3: check the real file's exact byte count first with wc -c needle.txt, then match units in find -size — c means bytes, no suffix means 512-byte blocks.

Level 5: cat shortcut "just working" is correct — symlinks transparently follow to their target when read. ls -l/readlink are how you notice it's a symlink at all.

Finished early? Try find ~/IT251/scavenger -perm 000 to find Level 2's file a different way, or find ~/IT251/scavenger -type l to find the symlink by type.

Self-check (optional)

Not graded, not submitted — just tells you what's actually correct so far, so you're not guessing before you submit. Write your six passwords into a file, one per line, in level order (0 through 5):

nano ~/IT251/scavenger-answers.txt

Then get the checker — download it directly, or paste it in yourself:

nano ~/it251-scavenger-check.sh
#!/usr/bin/env bash
# IT251 Lab 3 - self-check for the scavenger hunt. Not graded, not submitted -
# just compares what you recorded against what's actually in your own
# ~/IT251/scavenger tree right now, so you know what's correct before you submit.
set -uo pipefail

BASE="$HOME/IT251/scavenger"
ANSWERS="${1:-$HOME/IT251/scavenger-answers.txt}"

if [[ ! -d "$BASE" ]]; then
  echo "Can't find $BASE - run it251-scavenger-setup.sh first."
  exit 1
fi

if [[ ! -f "$ANSWERS" ]]; then
  cat <<MSG
Can't find your answers file at: $ANSWERS

Create it with the six passwords you found, one per line, in level order
(0 through 5):

  nano $ANSWERS

Then run this script again.
MSG
  exit 1
fi

mapfile -t LINES < "$ANSWERS"

correct=0
total=6

check() {
  local level="$1" expected_file="$2" got="$3" note="${4:-file not readable yet}"

  if [[ ! -r "$expected_file" ]]; then
    printf "  Level %s: SKIP  - %s\n" "$level" "$note"
    return
  fi

  local expected
  expected="$(cat "$expected_file")"
  got="$(printf '%s' "$got" | sed -e 's/[[:space:]]*$//' -e 's/^[[:space:]]*//')"

  if [[ "$got" == "$expected" ]]; then
    printf "  Level %s: CORRECT\n" "$level"
    correct=$((correct + 1))
  else
    printf "  Level %s: NOT YET - keep looking\n" "$level"
  fi
}

echo "IT251 Lab 3 - Scavenger Hunt self-check"
echo "Comparing $ANSWERS against your live ~/IT251/scavenger tree..."
echo ""

check 0 "$BASE/level0/.secret"                 "${LINES[0]:-}"
check 1 "$BASE/level1/--not a flag--.txt"      "${LINES[1]:-}"
check 2 "$BASE/level2/locked.txt"              "${LINES[2]:-}" "locked.txt still isn't readable - chmod it first"
check 3 "$BASE/level3/needle.txt"              "${LINES[3]:-}"
check 4 "$BASE/level4/deep/deeper/target.txt"  "${LINES[4]:-}"
check 5 "$BASE/level5/real-answer.txt"         "${LINES[5]:-}"

echo ""
echo "Score: $correct / $total correct so far."
if (( correct < total )); then
  echo "Not done yet - that's fine, this is a self-check, not a grade. Keep going."
else
  echo "All six found. Export your log and submit per the lab instructions."
fi

Run it:

bash ~/it251-scavenger-check.sh

The comparison is exact (whitespace at the ends is trimmed, but the text itself must match exactly what's in the file) — a "NOT YET" doesn't mean you're wrong conceptually, it usually just means a typo. Level 2 shows SKIP instead of a flat fail until you've actually fixed its permissions, since the checker genuinely can't read a 000-permission file either.

Submit

Run ~/it251-export-log.sh and submit the exported log plus the six recorded passwords, per LMS instructions.

grep / sort / diff — on your own data

cd ~/IT251/logs
ls -la
grep "cd" history_*.txt              # every line containing "cd"
grep -i "SUDO" history_*.txt         # case-insensitive
grep -c "ls" history_*.txt           # count matches per file
sort history_20260826_*.txt | less   # alphabetical, not chronological
diff history_20260826_*.txt history_20260902_*.txt   # what differs between sessions

grep -i (ignore case), -c (count), -v (invert) are the three flags worth memorizing. In diff output, lines starting < are only in the first file, > only in the second.

file — extensions lie, magic bytes don't

file /bin/ls
file ~/IT251/logs/history_*.txt
file ~/it251-export-log.sh
Security note: file reads a file's actual content, not its extension — a malicious file renamed .txt doesn't stop being an executable.

Cron — schedule a job

crontab -e

Add a line that appends the current time to a file every minute:

* * * * * date >> $HOME/IT251/logs/cron-test.txt

Five fields: minute, hour, day-of-month, month, day-of-week — each * means "every." Save/exit, then crontab -l to confirm it registered. Come back later and tail the file to see it actually ran unattended.

Common snags

Check here before raising a hand — most of these are quick fixes.

Lab 1 — VirtualBox & logging
SymptomLikely cause / fix
VM won't boot from ISOISO not attached in Storage settings, or boot order wrong — check Settings → Storage and Settings → System → Boot Order
Install hangs at a black/garbled screenGraphics/resolution issue — retry with the "safe graphics" or "compatibility" boot option in the ISO's boot menu
history file stays empty after setupStill in the old shell session — run source ~/.bashrc or open a fresh terminal, not just re-run the script
it251-export-log.sh: command not foundForgot chmod +x, or ran the bare name instead of ~/it251-export-log.sh
it251-export-log.sh dies with HISTFILE: parameter null or not setYour .bashrc/.zshrc has an older version of the logging block without export HISTFILE=.... Fix: open it in nano, add export HISTFILE="$HOME/.bash_history" (or .zsh_history for zsh) right above the HISTTIMEFORMAT/HISTSIZE lines inside the IT251 marker block, save, source ~/.bashrc, then re-run the export script
.bashrc edits didn't take effectSome distros' default terminal reads .bash_profile/.profile instead — open a brand-new terminal window to be safe
