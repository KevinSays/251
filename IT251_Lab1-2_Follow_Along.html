Create the VM

In VirtualBox: Machine → New

  • Name: IT251-<yourname>
  • Type/Version: match your distro (e.g., Linux / Ubuntu 64-bit)
  • Memory: 4096 MB minimum (2048 MB floor if the host is low on RAM)
  • CPU: 2 cores
  • Disk: 25 GB, dynamically allocated, VDI format
  • Attach the ISO under Storage → Optical Drive

Install the distro

Boot the VM and run the installer: language/keyboard, disk (use the whole virtual disk — no dual-boot risk, it's not real hardware), create a user account you'll remember all semester — this is what you'll be graded through.

First boot, update, snapshot

Debian / Ubuntu / Mint 
sudo apt update && sudo apt upgrade -y
Fedora 
sudo dnf upgrade -y
Shut down, then snapshot: Machine → Take Snapshot, name it clean-install. This is your safety net for the rest of the semester — break the VM later, roll back instead of reinstalling from scratch.

Persistent terminal history logging

This is the piece that makes every future lab auto-generate proof of work — run this once, and it keeps logging every session from here on. Open a terminal in your VM:

nano ~/it251-setup-logging.sh

Paste this in, save, exit:

#!/usr/bin/env bash
# IT251 - persistent terminal history logging setup. Run once.
set -euo pipefail

MARKER_START="# >>> IT251 history logging >>>"
MARKER_END="# <<< IT251 history logging <<<"
LOG_DIR="$HOME/IT251/logs"

case "$SHELL" in
  */zsh) RC_FILE="$HOME/.zshrc" ;;
  *)     RC_FILE="$HOME/.bashrc" ;;
esac

mkdir -p "$LOG_DIR"

if grep -qF "$MARKER_START" "$RC_FILE" 2>/dev/null; then
  echo "Logging block already present in $RC_FILE - nothing to do."
else
  {
    echo ""
    echo "$MARKER_START"
    if [[ "$RC_FILE" == *zshrc ]]; then
      cat <<'ZSH'
HISTFILE="$HOME/.zsh_history"
HISTSIZE=100000
SAVEHIST=100000
setopt INC_APPEND_HISTORY
setopt EXTENDED_HISTORY
ZSH
    else
      cat <<'BASH'
export HISTTIMEFORMAT="%F %T  "
export HISTSIZE=100000
export HISTFILESIZE=100000
shopt -s histappend
PROMPT_COMMAND="history -a; history -c; history -r${PROMPT_COMMAND:+; $PROMPT_COMMAND}"
BASH
    fi
    echo "$MARKER_END"
  } >> "$RC_FILE"
  echo "Added logging config to $RC_FILE."
fi

echo "Done. Run: source $RC_FILE   (or open a new terminal) then check with: history | tail"

Run it and reload your shell:

bash ~/it251-setup-logging.sh
source ~/.bashrc      # or: source ~/.zshrc
What does this actually do?

Every command gets a timestamp (HISTTIMEFORMAT). History writes to disk immediately after each command instead of only on exit, so a crash doesn't lose the log. History size is raised so a full semester of commands doesn't get silently truncated. The block is idempotent — running the script again won't duplicate it.

Second script — an export helper you'll reuse at the end of every future lab:

nano ~/it251-export-log.sh
#!/usr/bin/env bash
# IT251 - export current history to a timestamped file for lab submission.
set -euo pipefail

LOG_DIR="$HOME/IT251/logs"
mkdir -p "$LOG_DIR"
STAMP="$(date +%Y%m%d_%H%M%S)"
OUT="$LOG_DIR/history_${STAMP}.txt"

history -a   # flush current session's history to disk first
cp "${HISTFILE:-$HOME/.bash_history}" "$OUT"

echo "Exported history to: $OUT"
echo "Submit this file (or the whole ~/IT251/logs folder) as lab proof."
chmod +x ~/it251-export-log.sh

Navigation

pwd
cd /
ls
cd /home
ls
cd ~
pwd

pwd — where am I. cd — absolute vs. relative paths, ~, .., - for "previous directory". ls vs ls -l vs ls -la.

File & directory operations

mkdir ~/lab2-practice
cd ~/lab2-practice
touch notes.txt
mkdir subdir
cp notes.txt subdir/notes-copy.txt
mv notes.txt renamed-notes.txt
ls -l
rm subdir/notes-copy.txt
rmdir subdir      # only works if empty
No trash can: rm deletes for real. rmdir only removes empty directories; rm -r is recursive and deletes contents too — double-check the target before hitting enter, especially with wildcards.

Viewing files, redirection, man

echo "first line" > notes.txt
echo "second line" >> notes.txt
cat notes.txt
head -n 1 notes.txt
tail -n 1 notes.txt
less notes.txt        # q to quit
man ls

> overwrites, >> appends. | (pipe) sends one command's output into the next, e.g. ls -la | less. man <command> is the answer to "what does this flag do" for the rest of the semester.

SymptomLikely cause / fix
VM won't boot from ISOISO not attached in Storage settings, or boot order wrong — check Settings → Storage and Settings → System → Boot Order
