Networking

The box can't reach anything

A VM can't resolve any hostnames, but ping 8.8.8.8 (a raw IP) works fine.

Show answer

Diagnosis: routing/connectivity is fine — this is a DNS problem specifically, since a raw IP works but names don't.

Where to look: /etc/resolv.conf for a missing or unreachable nameserver, or nmcli/Netplan config if it's being managed and keeps getting overwritten.

Shell config

It works over SSH but not in a new terminal tab

A student added an alias to ~/.bash_profile. It works when they SSH in, but a new local terminal tab doesn't see it.

Show answer

Why: SSH sessions are login shells (read /etc/profile then ~/.bash_profile); a new terminal tab is typically an interactive non-login shell (reads ~/.bashrc only).

Fix: put the alias in ~/.bashrc instead — or have ~/.bash_profile source it, which is the common convention.

Backup & restore

Pick the right tool

You need to (a) archive a project folder to send to someone, and (b) keep a nightly incremental backup of a home directory.

Show answer

(a): tar -czvf project.tar.gz project/ — a single portable, compressed archive.

(b): rsync -a — incremental, only copies what changed, preserves permissions/ownership. tar would re-archive everything every night; rsync is built for exactly this job.

PATH

The wrong version keeps running

A student installed a newer Python version, but typing python3 still launches the old one. which python3 shows a path in /usr/bin, but the new install lives in /usr/local/bin.

Show answer

Diagnosis: both versions exist, but PATH is an ordered list, and the shell uses the first match it finds. If /usr/bin appears before /usr/local/bin in $PATH, the old version wins every time.

Fix: reorder PATH so /usr/local/bin comes first (edit the export line in ~/.bashrc), or call the new binary by its full path to confirm the theory before making it permanent.

Redirection

Where did the error message go?

A student runs grep pattern *.log > results.txt and expects a clean, empty terminal. Instead, a "No such file or directory" error still prints to the screen, even though the redirect looked correct.

Show answer

Why: > only redirects stdout (file descriptor 1). Error messages go to stderr (file descriptor 2), a separate stream that isn't touched by a plain >.

Fix: grep pattern *.log > results.txt 2>&1 merges stderr into the same redirect, or 2>/dev/null to discard errors specifically while keeping real output in the file.

Virtualization

Which network mode for this VM?

You're about to import a vulnerable target VM to practice against alongside your Kali VM. Both need to talk to each other, but neither should be reachable from the campus network.

Show answer

Host-only or Internal Network for both VMs — this isolates their traffic from the internet and the campus network entirely, while still letting them reach each other. NAT would let each VM reach the internet individually but wouldn't guarantee they can see each other on the same isolated segment; Bridged would expose them directly on the physical LAN, which is exactly what you don't want with a vulnerable target running.
